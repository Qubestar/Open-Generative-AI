# Vidmyo VFX engine

Imported from the Perfect VFX archive supplied by Luke on 2026-09-14; original director, themes, reference boards and renderer retained. Vidmyo integration uses existing local faster-whisper transcription and provider adapters rather than requiring another WhisperX environment. Runtime dependencies/browser are installed in the standard application-data VFX runtime folder (previously selected locations are reused), never inside the application bundle. Each render has its own public source. API keys stay in global encrypted Settings; project files record provider/model only.

Original archive supplies no license for its own content. Redistribution permission must be established before a public release. Remotion has separate licensing terms.

## Desktop workflow

1. Open **VFX** and choose a pre-edited local section plus an output folder. Choose intro, chapter card or custom. Use SDR BT.709, square pixels, constant frame rate, even dimensions and sections at most 180 seconds long. Vidmyo automatically bakes standard phone/camera display rotation into an app-owned project copy without modifying the original. Native dimensions including 4K are preserved. Silent chapter cards are supported.
2. Choose a supplied theme. The optional brand accent colors graphic highlights; headline fonts style large titles and numbers; body fonts style labels, lists and supporting copy. Vidmyo presents matched theme defaults, a color picker and curated Google Font choices. Select Codex, Claude Code, Gemini CLI or Hermes, or select API and enter an explicit OpenRouter model id. Sign in to local agents on the Agents page; add API keys in global Settings. Keys are never saved in VFX project files.
3. Inspect/transcribe locally using the existing Clipper/Cleaner transcription model and cache settings. Review candidate frame pairs and classify shots. Drop false cut candidates when the same shot continues; retained boundaries gate docking and animation windows.
4. Create the beat plan or use `vfx_open` / `vfx_submit_plan` through MCP. Local embedded planners receive the human-reviewed shot map and transcript; direct MCP agents can inspect the actual local frames. Project provider selection can change before a new plan. Creative direction, graphic text and the complete timing/payload spec remain editable. API planning discloses transcript/shot-map egress and billing in a native confirmation; footage is not uploaded. The director records a visual intent and thesis for every graphic and plans against the detected landscape, square or portrait canvas rather than scaling one composition across formats.
5. Vidmyo automatically prepares the renderer in the background on launch and retries when VFX opens, using its standard application-data folder outside the app bundle. Bundled npm runs through Electron’s Node runtime; general npm install scripts are disabled (only the pinned FFmpeg download installer is invoked explicitly), and FFprobe comes from Remotion’s platform compositor, and a pinned full FFmpeg download provides the scene, volume and PSNR filters absent from Remotion’s reduced FFmpeg. No system npm, Node, FFmpeg or FFprobe installation is needed for rendering. The existing local Python/transcription environment is still used for inspection. Preparation is shared across projects, verified before reuse and retried when rendering if needed. Google Fonts can require network during rendering.
6. Generate and review the storyboard. Vidmyo renders the real entrance, hold and exit frames for every planned event, overlays the selected platform's safe zone, and checks responsive layout, text capacity and subject framing. Any plan edit invalidates the storyboard. A full render stays disabled until the user checks the storyboard review box.
7. Approve the storyboard and render. Every run has isolated source linking and frozen props; concurrency inside one project is blocked. H.264 CRF16 uses PNG intermediates and limited-range BT.709. Source audio packets are copied, not re-encoded. PCM/other audio incompatible with MP4 selects a baked MOV container.
8. Inspect the rendered video, event midpoints, subscribe click and cut pairs against the matching landscape or portrait theme board. Numerical gates check dimensions, FPS, frame count, source fingerprint, audio stream hashes, BT.709 and a clean-segment PSNR threshold of 35 dB when a suitable clean stretch exists. Visual review remains required: numerical gates cannot prove face placement, typography or motion quality. Accept the finished section and show its files for your editing timeline.

Each project retains `vfx.json`, a reviewed intake/shot map, transcript, renderer spec, parity measurements, review frames and `run-log.md`. Clean footage stretches and all graphic events are included in the audit chart. MCP submits a plan for desktop review; it cannot approve or trigger a render itself.

## Integration changes to supplied renderer

- Composition frame count uses the host's decoded source count instead of duration rounding.
- Split-screen statement/chart payloads now render; the supplied version drew an empty panel for a statement without items.
- Outro-safe overlay statements support an explicit `endscreenSafe` upper-left layout.
- Portrait projects use dedicated vertical composition grammar: aspect-preserved creator cards, full-bleed footage with a lower subject-safe stage, vertically stacked diagrams, short-side typography and Shorts/TikTok/Reels safe-zone profiles.
- Each supplied theme now includes landscape and portrait reference boards.

Verification is recorded under the repository's `.tmp/vfx/`. Live paid API and account-specific CLI requests are not exercised by the offline checks; their shared adapters are covered by existing provider tests.
